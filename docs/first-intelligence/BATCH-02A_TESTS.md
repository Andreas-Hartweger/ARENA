# Batch 02A – Testkatalog / TF-17–18

Alle Fälle sind verpflichtende Abnahmepunkte, keine Behauptung bereits ausgeführter Tests. Mehrere Fälle dürfen in einem Vitest-Test zusammengefasst sein; jeder ID muss eine nachvollziehbare Evidenz zugeordnet werden. Referenzwerte aus den vorhandenen Specs beibehalten. Diskrete Werte, Reihenfolgen, Masken und gleicher Seed im selben Runtime exakt; numerische analytische Fixtures abs 1e-9 m bzw. 1e-12 bei dimensionslosen kleinen NN-Beispielen, Referenz/Index abs 1e-8 m (Ties gesondert prüfen). Bei größerem Maßstab begründete absolute/relative Toleranz explizit dokumentieren; niemals bestehende Tests aufweichen, um Regressionen zu verstecken. Numerische Grenzfälle separat. Browser-/Node-Transzendenten können abweichen; gleiche Runtime deterministisch, Cross-Runtime Vergleich dokumentieren und FPS-Unabhängigkeit nachweisen.

## Benchmark-Protokoll

- Fixierte SHA, Laufzeit/OS/CPU/GPU/RAM, Browser/DPR/Resolution, Profil/Architektur/Seed, Warmup, Kandidatenzahl und exakte Szenarien. Keine FPS allein als KI-Durchsatz verkaufen.
- Vorschlag: mindestens 600 Warmup-Ticks (bzw. 1000 isolierte Calls), 3 unabhängige Messwiederholungen je Fall, >=5 s Messzeit je Kernfall soweit praktikabel; bei sehr teurer Last realistische Begrenzung dokumentieren. Monotone Zeit, Median/P95 aus klar benannten Samples, min/max, Anzahl, RSS/Heap soweit API möglich, Fehlerrate. Separate Sensor-/Inference-/Weltzeit. 100 Kandidaten sind Benchmarkgröße, nicht finale Populationsentscheidung.
- Rohdaten CSV/JSON + menschenlesbare Zusammenfassung. Optimierung nur mit korrekter Referenz; kein Anspruch auf bestimmte 10×/100× Trainingsrate. Bei schlechterer Leistung begründen/gezielt optimieren, kein Feature-Scope erweitern.
- Browserbelege inkl. Screenshot Sensor/Brain Inspector, bekannte Gewichte/Aktivierung, Step und Fehlerfall; Logs ohne sensible Daten. `npm run check` + `npm run calibrate` mit echter Ausgabe, Zeit und SHA. PASS/FAIL/NOT RUN je ID, Grund und Fundstelle. Kein Weglassen fehlender Tests. Native Alt+Tab braucht menschliche Evidenz falls nicht automatisierbar.
