Immutable nach Dispatch; Änderung neuer Versuch. Job uses existing 02C run/session/segment/generation/slot/scenario/attempt/lease, canonical score order. Keine zweite Engine. IDs und Seeds unabhängig; D11 FNV/Mulberry, Float64 canonical +0, SHA framing unverändert. Scenario seed getrennt von evolution/master; keine hidden evaluator Infos. Training-Szenarien gehören zum Eval-Vertrag, Dev und Holdout werden mit separatem Runner ohne Reproduktion ausgewertet.

## Adapter und Start
PRE-D01 liest tatsächliche 02C Ports, vollständige Tests/CLI/Browser-Persistenz, rekonstruiert optional Node-Storage Adapter auf gemeinsamen Datenverträgen. Der Zwischenstand besitzt stepEpisode Generator + evaluate Wrapper, WorkerPool und Node compute port; aktueller Runner ist auf Seed42 und einfache Modi begrenzt, kein ausreichender Research Coordinator. Erweiterung mit validierter generalisierter Config und tatsächlichem CP-Hydrate statt zweiter Pipeline. Keine Behauptung, zukünftige APIs seien bereits vorhanden. Neue Node lokale Evidence/Checkpoint-Adapter dürfen D13 Referenzen nicht umgehen. Kein stilles volatile Resume. Atomic manifest before jobs, commit generation mit canonical order, durable CP vor nächstem Dispatch, staged output und hash checks; bei Crash letzten konsistenten Boundary laden, neue session, Budgetverbrauch separat. Wiederholung niemals Ergebnisse doppelt veröffentlichen. Warm resume reproduziert Genome, Statistiken und RNG; wall-clock nicht Teil Fitness. Side tasks isolieren gemäß TR01–08.

Academy/GT01, Standard start -8m, standard 120s/7200ticks, 300 grace/900 without 2m progress, existing 1..1e6 laps. Alternative starts vor erster Startlinie mit lokalem station, seitlichem offset, heading und velocity entlang Fahrzeugrichtung. Validate finite, track placement and OBB footprint inside permissible surface, no obstacle overlap, start before gate, valid local projection, coherent initial lap and ledger, no unearned approach/gates; derive approach length from actual start station. Explicit signed road offset convention, units SI. Scenario manifest contains normalized effective values, full contract, version and digest. Standard hash and exact reference must stay identical; new fields absent on legacy path. New task 3 laps max21600ticks with existing no-progress; no reset at lap boundary. Recovery separate objective/task and analysis, never invent completion score from standard fitness. For Recovery start in valid collision-free physical state (may be grass or misaligned); return when all wheel/footprint checks for lawful road state, forward direction with heading within 30°, positive forward speed, no overlap, valid projection; proposed recovery proof then >=20m accepted new forward progress within 300 ticks, no invalidation/teleport/severe contact; return <=1200ticks. These threshold details are implementation proposals, not additional user votes; use independently tested ledger, not hidden reward inputs. If new task unsupported, implement/test explicit contract or block affected task, no fake evidence.

## Curriculum & research variants
First use existing configs. New reward curves/sensor ablation may be investigated via separate versioned experimental contracts only if within approved scope and validated. Protect D08–D11 standard; no changes to base formulas, collision/physics, output adapter, clipping, initializers, no-progress or RNG. Curriculum change evaluation contract -> new segment, re-evaluate retained full population, no mixed scores, preserve logical counters; architecture/population incompatibility -> new run. Compare with equal overall episode/tick budgets. Different models cannot silently exchange weights. New architecture and learning technologies post-launch; no new dependencies.

## Evidence schema and ordering
`campaign.json`: budget/ledger version, approved caps, immutable matrix hash, repository SHA, runtime identity, start/end and status. `experiment.json`: definition, selected config digest, hypothesis, seeds, model/scenario contracts, assigned machine, start/end, outcome, attempts and artifact references. `generations.ndjson`: actual committed generation, segment, candidate/episode counts, ordered score statistics, success counts, valid time quantiles, diversity, best/champion fingerprints, duration/tick counters, checkpoint ID. `episodes.ndjson`: job/attempt identity, terminal reason, lawful progress, lap times, fitness components, unsaturated raw errors, actual ticks, model hash; non-score failures separate. `selection.json`: evaluated candidate hashes, fixed Dev panel hash, ranking/metrics, chosen IDs/reasons and cutoff budget, frozen before next stage. `validation.json`: frozen candidate/role, panel manifest, complete per-case records, exact thresholds and pass/fail/unknown, independent reviewer and commit. `promotion.json`: official model immutable version, SHA, compatible contracts, validation and audit references, rollback pointer. JSON finite values only; null for absent metrics. SHA256 manifests for files, schema/version and byte length; deterministic canonical ordering. Store actual raw data and verified relative paths or explicit external artifact locator. Reject missing/changed artifact.
Dev panel generation and measurement ports in RS-003/005 must be available before RS-007/008/009 selection; RS-010 is final frozen holdout and audit, not the first Dev evaluation. If budget limits stop the nominal matrix, show per-stage counts and reasoning, preserve reserve. Optional research-specific tests may be not applicable with explicit reasons, but required software/fault/regression/gate tests cannot be waived.
