# Trainingssteuerung und Automatisierung · TF-C09–14
## State Machine
Draft -> Validating -> Queued or Initializing -> Running; Initializing creates resources and initial durable CP before dispatch (unless explicit volatile mode). Failure releases resources and records reason. Running -> Pausing -> Paused -> Resuming -> Running; separate Draining (no new jobs; active finish then paused). Running -> Stopping (finish current full generation) -> Completed; Cancel from active/paused/stopping -> Cancelling -> Cancelled. Fault -> Faulted/Recoverable, no auto next. Session includes one active lease even paused. Commands serialized, commandId duplicate idempotent, old seq/session rejected. Cancel before publish wins, after atomic commit preserves commit; terminal state rejects stale Resume. Stop while paused does not secretly resume: ask explicit resume-to-finish or cancel. Pause at safe tick or atomic publish boundary. ACK all active workers and coordinator; no false Paused. No partial selection. Preflight validates all model/task/fitness/architecture/operator/budget/resource/queue references before allocation. Frozen initial config + immutable revisions. Template edits not affect Run.

Typed expression tree with allowlisted goal types, no code. AND/OR flat groups v1, optional required consecutive generations, false/null if required lap result absent. Predeclare thresholds and metrics; goal evaluation after complete results before next reproduction; record why stopped. Hard max evaluated generations/episodes checked before whole next generation, default 100 G0..99, 128×1 episodes=12800. Real active wall time excludes pause, includes runtime orchestration and mandatory saves; soft limit at next full boundary (finish) or explicit hard limit abort incomplete; never fitness. Hard time monitor separate from simulated deadline. Retries cost measured wall but not logical evaluation. If crash unknown active interval, document lower bound and require user decision/conservative remaining budget before resume; no silent replenishment. Plateau disabled unless selected; D11 adaptive independent. Validation/holdout not used in automatic training selection unless explicit separate validated goal contract; no holdout leakage.
## Revisions and segments
Runtime controls (display, speed, worker/resource) safe boundary, no seed changes. Learning operators (mutation/cross/selection/adaption config within existing supported ranges) pending for next reproduction boundary; immutable revision applied before staging descendants, record version; if already committed, apply later, never alter published descendants. Do not mix adaptive state with incompatible policy: explicit reset of changed operator-related adaptive baselines and audit; ordinary uninterrupted reference unaffected. Fitness/scenario/task change: complete old generation, retain evaluated population, start new segment with full retained compatible population, re-evaluate all under new contract before selection; no implicit new random/seeded population. Global run counters monotone, segment local generation starts 0, explicit segment-index seed domain as D11. New segment reset champion/comparison/adaptive refs, previous segment remains historical. Change after commit waits next safe boundary; no redo without explicit branch. Incompatible signature (vehicle/sensor frequency/layout/architecture) rejected in same segment; new compatible model/run or documented migration later, never silently remap. Pop size changes new Run v1. D11 config frozen implementation needs stage adapter; if incompatible with existing contract report to A; no silent compromise.
## Queue and experiment
32 waiting + 1 active. Each QueueEntry ID+revision+full validated snapshot+explicit source version refs+order+autoStart flag; reorder/delete/edit waiting, edit creates revision and revalidation. Automatic start opt-in for each batch/order; only normal Completed with queue enabled, not Cancel/Fault/Pause/recovery. Preflight again at dispatch; missing resources/source block queue and notify. Persistence via D13, recovery always disabled until user re-enables. Series explicit lists of values×seeds, preview cardinality (overflow checked before materialization), shared series budget (sum logical budgets, optional active time), per-run independent IDs/records. Example 3 rates ×3 seeds=9 runs; 128×100×9=115200 evaluations. No automatic new experiments, no arbitrary code or hidden policy search. D14 studies actual learning; UI may compare completed records.
