## v1 Container
ZIP-based .arena-model / .arena-checkpoint / .arena-backup. Manifest identifies magic `arena.package`, formatVersion=1, type, IDs, required runtime/model contracts, canonical entries {path,byteLength,sha256,role}, root refs. `manifest.json` UTF8 strict, `data/*.json` metadata, `genomes/<id>.bin` approved IDs, optional selected evidence metadata only. Exact schema/allowlisted fields, strict finite numbers, depth/array/string bounds, reject duplicate JSON keys/unknown mandatory version. No executable files, nested archives, symlink, absolute/traversal, drive paths, NUL, duplicate/case-alias or unicode/path ambiguity. No auto extract to arbitrary files. Required refs transitive closure. No authority from metadata. Entry raw SHA256 over bytes; manifest hash for transport integrity optional sidecar (not signature). ZIP CRC32 independent. No compression necessary to v1: proposed STORE-only writer/parser (standard ZIP with documented UTF8 flag, no encryption/ZIP64/multidisk/data descriptors unless tested explicit supported version). Reject unsupported method explicitly; later audited deflate support after approval. No new dependency unapproved; if safe parser needs dependency, request approval rather than invent unsafe decompressor. Validate EOCD/central/local offsets, lengths/method/flags and exact boundaries; no overlaps/extra hidden data; enforce actual streamed bytes not header claims. v1 conservative TF-C limits compressed/expanded <=1GiB and effective free storage+RAM staging budget; <=16384 entries, manifest<=8MiB, per entry<=64MiB (large populations split by genome), metadata JSON<=8MiB per entry, depth<=32, filename<=160 ASCII allowlist; lower effective limits from resource manager. Limits versioned and benchmarked; no permanent super-KI cap. Reject rather than allocate based on untrusted size. No read all+copy 1GiB in memory; bounded staging chunks, cancel cleanup, preflight before publication. For a very large valid package beyond available limits give explicit split/backup options. Export uses pinned consistent read revision; complete manifest/hash before user-visible success, cannot guarantee file persisted outside browser.

Foundation `arena.dense.float64.v1` exact row-major weights per layer then bias block; Float64LE, count=architecture derived, length=8×count, finite, per-weight/bias bounds. Actual 02B Genome normalizes -0 -> +0. Canonical ARENA exports +0; raw file integrity hash first. Noncanonical -0 imported external package: reject as noncanonical v1 or explicit new import conversion preserving original outside claimed byte-roundtrip; do not silently change a claimed exact checkpoint. Fingerprint = SHA256(uint32LE UTF8 header length || uint32LE param count || canonical model.key UTF8 || canonical LE parameter bytes); raw SHA256 separate. Hash equality followed by exact contract/content compare, collision buckets. Model limits validated separately because model.key excludes limits. Use reference_vectors.json for independent encoding fixture; existing 02B header canonical function retained. Browser async crypto integrated by staged adapter or verified sync SHA (no unapproved dependency), preserve exact order/hash; node reference unchanged. Future tensor type/layout and multiple blocks explicit new versions, unknown not accepted.
## Compatibility dimensions
Execution: signature/layout/input/controller/architecture/dtype/runtime supported, approved vehicle/sensor. Train: execution plus allowed operators/bounds/task/config. Resume: full checkpoint, complete graph, exact required runtime contracts, deterministic environment eligibility; older incompatible may start a new model-based run not exact continuation. Parameter comparison: same mapping/model key/precision (different limits do not imply same training contract). Performance comparison: common benchmark contract/task/conditions and comparable metrics, may run different architectures with approved equivalent allowed inputs; do not mix raw fitness. Return per-dimension yes/no/unknown and reason. Model ability vs technical compatibility separate. Provenance imported claims unverified; official status only trusted catalog, later signatures. Same ID same content idempotent; same ID different content conflict, offer new independent IDs/variant, remap transitive refs atomically; never overwrite. Older checkpoint if newer history exists -> new branch ID, preserve parent; transferred Run resumes only after explicit user confirms source not concurrently active (cross-computer cannot enforce globally). Queue imported disabled. Restore fresh origin requires complete dependencies; no hidden external resource paths.
